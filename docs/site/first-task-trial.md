# Try your first task

Follow the [quickstart](./getting-started.md) in a small project. Choose a change you can review, such as a greeting function with a test or a health endpoint.

Review the plan before execution. When Rivet reaches `awaiting-final-approval`, inspect the changed files and the checks shown by `rivet task status`. This is your opportunity to review the result before delivery.

If setup or execution fails, follow [troubleshooting](./troubleshooting.md). When reporting a bug, include your operating system, Rivet and harness versions, the command and the error, with private information removed.

For a structured contributor test, see the [onboarding study](https://github.com/FraneAgilno/rivet/blob/main/docs/maintainers/first-task-trial.md).
